# Summar

Учебный проект на Python для суммаризации текста и дообучения русскоязычной модели.

Основная модель проекта:

- `checkpoints/rut5-absum-finetuned`

Это дообученная версия `cointegrated/rut5-base-absum` для обычных
информационных, объяснительных и современных художественных текстов. Базовая
модель хранится в `models/rut5-base-absum`, а готовый чекпоинт — в
`checkpoints/rut5-absum-finetuned`. Старую классическую прозу пока считаем
отдельным направлением дальнейшей работы.

## Структура проекта

- `main.py` — запуск суммаризации из консоли
- `run_api.py` — запуск API на FastAPI
- `train_model.py` — запуск дообучения
- `src/summar/model.py` — логика суммаризации
- `src/summar/train.py` — логика обучения
- `data/train.json` — 159 обучающих примеров
- `data/validation.json` — 41 пример для проверки
- `data/dataset_notes.md` — пояснения по формату датасета
- `test_texts/` — пять постоянных текстов, которые не участвуют в обучении
- `evaluate_model.py` — ручной запуск постоянного тестового набора

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install -e .
```

## Быстрый запуск

Если у тебя уже скачана модель:

```bash
python main.py --input-file text.txt
```

Эта команда автоматически использует дообученную модель
`checkpoints/rut5-absum-finetuned`.
Для явного выбора можно выполнить:

```bash
python main.py --model-name checkpoints/rut5-absum-finetuned --input-file text.txt
```

Если модель нужно скачать отдельно:

```bash
python download_model.py
```

## Что показывает вывод

После суммаризации проект выводит:

- само краткое содержание;
- количество символов в исходном тексте;
- количество символов в сокращённом тексте;
- процент сокращения.

## Дообучение на своих примерах

В папке `data/` находится датасет из 200 пар: 159 примеров используются
для обучения, а 41 отдельный пример — для проверки. Текущий состав специально
усиливает жанры, в которых постоянные тесты обнаружили ошибки:

- 29% информационных и деловых текстов;
- 33% учебных и объяснительных текстов;
- 38% художественных текстов, включая классическую стилизацию.

Краткие содержания написаны в нейтральном стиле и занимают в среднем около
30% от длины исходного текста.

Формат одной записи:

```json
{
  "text": "Полный текст",
  "summary": "Краткое содержание"
}
```

### Запуск дообучения на локальных файлах

```bash
python train_model.py --train-file data/train.json --validation-file data/validation.json --text-column text --summary-column summary --model-name models/rut5-base-absum --output-dir checkpoints/rut5-absum-finetuned --epochs 3
```

После обучения новая версия сохранится в `checkpoints/rut5-absum-finetuned`.
Старые чекпоинты при этом останутся без изменений.

После сохранения чекпоинта модель автоматически проходит пять постоянных
тестов из `test_texts/`. Отчёт сохраняется в
`checkpoints/rut5-absum-finetuned/test_results.json`. Автоматический прогон
можно отключить флагом `--skip-test-run`.

## Проверка дообученной модели

После обучения можно запускать уже новый чекпоинт:

```bash
python main.py --model-name checkpoints/rut5-absum-finetuned --input-file text.txt
```

После каждого дообучения проверяйте текущую модель на одних и тех же текстах,
которых нет в `train.json` и `validation.json`. Так можно отслеживать сохранение
главной мысли, отрицаний, причинно-следственных связей, фактическую точность,
пунктуацию и отсутствие оборванных предложений.

## Постоянные тесты

Набор включает пять жанров: информационный, учебный, деловой, современный
художественный и классическую прозу. Эти тексты не входят ни в `train.json`,
ни в `validation.json` и не должны добавляться туда в будущем.

Запустить тесты вручную для основной модели можно одной командой:

```bash
python evaluate_model.py
```

Результат записывается в `results/test_results.json`. Для каждого текста отчёт
содержит пересказ, процент сокращения, совпадение слов с эталоном и долю
трёхсловных фрагментов, скопированных из исходника.

## Что делать дальше

1. Использовать `rut5-absum-finetuned` как основную модель для обычных текстов.
2. Сохранить неудачные результаты и определить повторяющиеся смысловые ошибки.
3. Добавлять новые примеры под найденные ошибки, не перенося тестовые тексты в обучение.
4. Работу со старой классической прозой продолжить отдельным этапом.
5. После стабилизации качества подключить модель к API и пользовательскому интерфейсу.
