# Summar

`Summar` — учебный проект на Python для автоматического создания краткого
пересказа русскоязычного текста. Модель не просто выбирает предложения из
исходника, а генерирует новое краткое содержание своими словами.

Проект умеет:

- суммаризировать текст из файла через консоль;
- показывать длину исходного текста, длину пересказа и процент сокращения;
- дообучать русскоязычную модель на собственном датасете;
- автоматически проверять новый чекпоинт на пяти постоянных текстах.

Основная рабочая модель — `checkpoints/rut5-absum-finetuned`, дообученная
версия `cointegrated/rut5-base-absum`. Она предназначена прежде всего для
информационных, учебных, деловых и современных художественных текстов.
Классическая проза пока остаётся отдельным сложным направлением.

## Главные команды

Все команды выполняются из корня проекта в PowerShell.

### 1. Установка

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install -e .
```

### 2. Суммаризация текста

Поместите исходный текст в `text.txt` и выполните:

```powershell
python main.py --input-file text.txt
```

По умолчанию используется `checkpoints/rut5-absum-finetuned`. Другой
чекпоинт можно указать явно:

```powershell
python main.py --model-name checkpoints/rut5-absum-finetuned-v3 --input-file text.txt
```

В результате программа выведет краткое содержание, количество символов в
исходнике и пересказе, а также процент сокращения.

### 3. Загрузка базовой модели

```powershell
python download_model.py
```

Скрипт сохраняет модель в `models/rut5-base-absum` и умеет продолжать
прерванную загрузку.

### 4. Дообучение

Перед обучением проверьте длину пересказов, долю копирования и отсутствие
повторяющихся шаблонов в датасете:

```powershell
python audit_dataset.py
```

Команда в одну строку для копирования:

```powershell
python train_model.py --train-file data/train.json --validation-file data/validation.json --text-column text --summary-column summary --model-name models/rut5-base-absum --output-dir checkpoints/rut5-absum-finetuned-v10 --epochs 4 --learning-rate 5e-5 --label-smoothing-factor 0 --early-stopping-patience 2
```

Новая версия будет записана в `checkpoints/rut5-absum-finetuned-v10`, поэтому
текущая рабочая модель не перезапишется. После обучения автоматически
запускаются пять постоянных тестов, а отчёт сохраняется в
`checkpoints/rut5-absum-finetuned-v10/test_results.json`.

После успешного сохранения итоговой модели промежуточные папки `checkpoint-*`
удаляются автоматически, чтобы каждый запуск обучения не занимал несколько
лишних гигабайт. Для отладки их можно сохранить флагом
`--keep-intermediate-checkpoints`.

Автоматическую проверку можно отключить аргументом `--skip-test-run`.

### 5. Проверка модели

Проверка основной модели:

```powershell
python evaluate_model.py
```

Проверка экспериментального чекпоинта:

```powershell
python evaluate_model.py --model-name checkpoints/rut5-absum-finetuned-v10 --output results/v10_test_results.json
```

### 6. Тесты проекта

```powershell
python -m pytest -q
```

занимают много места и хранятся локально.

## Как работает суммаризация

1. `main.py` передаёт управление модулю `src/summar/cli.py`.
2. CLI читает исходный файл и нормализует текст.
3. `SummarizationModel` загружает токенизатор и выбранный чекпоинт.
4. Текст преобразуется в токены. Слишком длинный текст делится на части только
   при превышении допустимого числа токенов.
5. Модель RuT5 генерирует новый краткий пересказ, а не извлекает готовые
   предложения.
6. Результат очищается от повторов и незавершённых фрагментов.
7. CLI рассчитывает длину обоих текстов и фактический процент сокращения.

Целевая длина пересказа составляет примерно 30% исходного текста, то есть
сокращение — около 70%. Точное значение может отличаться, поскольку модель
завершает мысль целым предложением.

## Как работает обучение

Датасет содержит `400` пар: `280` примеров (70%) используются для обучения,
а `120` (30%) — для validation. Формат
одной записи:

```json
{
  "text": "Полный исходный текст",
  "summary": "Короткий нейтральный пересказ своими словами"
}
```

Проверочная выборка, которую часто называют тестовой, в проекте хранится в
`validation.json`, потому что она используется для контроля ошибки во время
обучения. Пять текстов из `test_texts/` не участвуют в настройке модели и
остаются отдельным финальным тестом.

Примерное распределение жанров: 34% информационно-деловых, 31% учебных и 35%
художественных текстов. Подробные правила описаны в `data/dataset_notes.md`.

Во время обучения `src/summar/train.py`:

1. загружает и проверяет JSON-файлы;
2. токенизирует исходники и эталонные пересказы;
3. дообучает выбранный чекпоинт с заданными параметрами оптимизации;
4. регулярно вычисляет ошибку на validation;
5. применяет раннюю остановку и восстанавливает лучший чекпоинт;
6. сохраняет модель в новую папку;
7. запускает постоянный тестовый набор.

## Постоянные тесты

В `test_texts/` находятся пять текстов разных жанров: информационный, учебный,
деловой, современный художественный и классическая проза. Их нельзя переносить
в `train.json` или `validation.json`, иначе сравнение моделей станет нечестным.

Для каждого пересказа отчёт содержит:

- процент сокращения;
- совпадение слов с эталонным summary;
- долю трёхсловных фрагментов, скопированных из исходника;
- полный текст результата для ручной проверки смысла и связности.

Числовых метрик недостаточно для окончательного выбора модели. Нужно также
проверять сохранение отрицаний, причин и следствий, фактическую точность,
пунктуацию и отсутствие оборванных предложений.

## Результаты эксперимента v10

`v10` обучена от базовой `models/rut5-base-absum` на датасете из 400 пар:
280 примеров использовались для обучения и 120 для validation. Обучение на CPU
заняло 19 минут 37 секунд. Итоговый validation-loss составил `2.486`.

| Модель | Среднее сокращение | Token F1 | Копирование исходника |
| --- | ---: | ---: | ---: |
| Стабильная | 69,20% | 0,1450 | 0,5045 |
| v8 | 70,96% | 0,1437 | 0,3265 |
| v9 | 72,48% | 0,1361 | 0,2993 |
| v10 | 73,18% | 0,1732 | 0,3041 |

`v10` точнее выдерживает целевое сокращение и получила лучший `Token F1` среди
сравниваемых версий. Учебный текст пересказан связно и без смысловых искажений.
В остальных жанрах ручная проверка всё ещё обнаруживает ошибки в отрицаниях,
причинно-следственных связях и согласовании слов, поэтому стабильный чекпоинт
пока не заменён. Полный отчёт, включая неудачные ответы, находится в
`experiment_results/v10/`.

## Лучший пример v10

**Исходный текст**

> Повторное чтение создаёт ощущение, что материал хорошо запомнился, потому что
> знакомые предложения легко узнаются. Но узнавание текста не означает, что
> человек сможет самостоятельно восстановить его смысл или применить идею в
> новой задаче. Для более надёжной проверки полезно закрыть источник и попытаться
> объяснить содержание своими словами, привести собственный пример или ответить
> на вопрос без подсказки. Ошибки при таком воспроизведении показывают пробелы,
> которые оставались незаметными во время чтения. Активное вспоминание кажется
> более трудным и медленным, однако именно это усилие укрепляет память. Поэтому
> эффективность обучения определяется не количеством перечитываний, а
> способностью воспроизвести и использовать знание без опоры на исходный текст.

**Краткий пересказ модели**

> Повторное чтение создаёт ощущение, что материал хорошо запомнился, потому что
> знакомые предложения легко узнаются. Проверка и воспроизведение помогают
> восстановить смысл и применить идею в новой задаче.

Результат содержит 202 символа вместо 762: текст сокращён на `73,5%`.
