# Dataset Notes

В папке лежит набор примеров для дообучения модели суммаризации.

- `train.json` — 175 обучающих примеров (70%)
- `validation.json` — 75 проверочных примеров (30%)

Всего в датасете 250 пар: 70% отведено на обучение и 30% на проверочную
выборку. Общий состав включает 75 информационно-деловых, 80 учебных и
95 художественных текстов.

В коде 30-процентная проверочная выборка называется `validation`, поскольку
по ней контролируется обучение. Это не постоянный демонстрационный набор из
папки `test_texts/`, который остаётся полностью независимым.

Связанные между собой новые примеры хранятся только в обучающей части. Для
validation выбраны отдельные старые тексты с фиксированным seed, чтобы похожие
шаблоны не попадали одновременно в обе выборки и не улучшали метрики искусственно.

Последняя порция из 80 примеров усиливает учебные тексты и классическую прозу:
отрицания, противопоставления, причинно-следственные связи, метафоры,
внутреннюю речь и различие между ожиданием героя и фактическим результатом.

Дополнительные 6 примеров направлены на ошибки последней экспериментальной
модели: подмену причин в рабочих процессах и потерю мотива героя в современной
художественной прозе.

Последние 44 примера добавлены по результатам постоянных тестов. Они усиливают
сохранение причины и результата, работу с отрицаниями, проверку понимания,
мотивы героев и нейтральный пересказ художественных образов.

## Формат записи

```json
{
  "text": "Полный исходный текст",
  "summary": "Краткий пересказ"
}
```

## Целевой состав датасета

Текущий состав специально смещён в сторону обнаруженных слабых жанров:

1. 30% информационно-деловых текстов.
2. 32% учебных или нейтральных объяснительных текстов.
3. 38% художественных фрагментов, включая классическую стилизацию.

Такой баланс нужен, чтобы модель не привыкала только к новостному или деловому стилю и могла адекватно пересказывать более образные тексты.

## Каким должен быть `summary`

Во всех группах текстов summary лучше держать в одном стиле:

1. Понятный нейтральный пересказ.
2. Короткая и собранная формулировка.
3. Сохранение главной мысли, причин и итога.
4. Минимум дословных заимствований из исходника.
5. Без тяжёлых художественных оборотов, даже если исходный текст литературный.

## Чего лучше избегать

1. Набора фраз, просто вырезанных из исходного текста.
2. Слишком длинных summary, которые почти повторяют структуру оригинала.
3. Резкой смеси стилей внутри summary.
4. Художественного пересказа для обычных учебных и информационных текстов.
5. Коротких исходников, в которых модели нечему учиться сжатию и переформулировке.

## Что делать дальше

1. Проверить модель на неизменном наборе пользовательских текстов.
2. Отмечать типичные ошибки: потерю факта, искажение смысла, обрыв фразы и копирование.
3. Следующую порцию данных подбирать прежде всего под обнаруженные ошибки.
4. После каждого расширения заново обучать модель с одинаковыми параметрами и сравнивать результат.
