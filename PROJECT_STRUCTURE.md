# Project Structure

Этот файл описывает структуру проекта `Summar`, главные файлы, связи между ними и используемые технологии.

## Общая идея проекта

Проект предназначен для суммаризации текста на Python.

Он умеет:

- принимать текст;
- передавать его в модель суммаризации;
- выводить краткое содержание;
- дообучать модель на своих примерах;
- при необходимости запускаться как API.

## Основные технологии

### Язык и основа

- `Python` — основной язык проекта

### Нейросеть и NLP

- `transformers` — загрузка и запуск модели
- `torch` — работа модели на PyTorch
- `sentencepiece` — токенизация для T5-подобных моделей
- `datasets` — загрузка датасетов для обучения
- `evaluate` — метрики качества при обучении

### API

- `FastAPI` — серверная часть для будущего сайта или приложения
- `uvicorn` — запуск API-сервера

### Тесты

- `unittest` — базовая проверка логики проекта

## Корень проекта

Главные файлы в корне:

- `main.py` — точка входа для обычной суммаризации
- `train_model.py` — точка входа для дообучения
- `run_api.py` — запуск API
- `download_model.py` — скачивание базовой модели
- `README.md` — инструкция по запуску
- `PROJECT_STRUCTURE.md` — этот обзорный файл
- `requirements.txt` — зависимости проекта
- `pyproject.toml` — настройки пакета и тестов

## Папка src/summar

Это основная логика проекта.

### `config.py`

Хранит конфигурации:

- имя модели по умолчанию;
- параметры суммаризации;
- параметры обучения.

Используется в:

- `model.py`
- `cli.py`
- `train.py`
- `api.py`

### `preprocessing.py`

Отвечает за подготовку текста:

- очистка пробелов;
- разбиение на предложения;
- разбиение длинного текста на части.

Используется в:

- `model.py`
- `cli.py`
- тестах

### `model.py`

Главный файл логики суммаризации.

Что делает:

- загружает модель и токенайзер;
- определяет, откуда брать модель;
- запускает генерацию краткого содержания;
- выполняет повторную генерацию, если summary слишком короткое;
- очищает итоговый результат.

Это центральный файл проекта.

Используется в:

- `cli.py`
- `api.py`
- `compare`-логике, если её снова добавить позже

### `cli.py`

Консольный интерфейс проекта.

Что делает:

- получает текст из аргументов или файла;
- создаёт объект модели;
- запускает суммаризацию;
- выводит результат и статистику по символам.

Связь:

- `main.py` вызывает `cli.py`

### `api.py`

API-обёртка над моделью.

Что делает:

- поднимает FastAPI-приложение;
- принимает текст через HTTP;
- вызывает суммаризацию;
- возвращает результат в JSON.

Связь:

- `run_api.py` запускает `api.py`

### `train.py`

Файл логики дообучения.

Что делает:

- загружает train/validation датасет;
- токенизирует пары `text -> summary`;
- запускает `Seq2SeqTrainer`;
- сохраняет новый чекпоинт модели.

Связь:

- `train_model.py` вызывает `train.py`

## Папка data

Папка для данных дообучения.

Файлы:

- `train.json` — обучающие примеры
- `validation.json` — проверочные примеры
- `dataset_notes.md` — пояснение по формату данных

Формат записи:

```json
{
  "text": "Исходный текст",
  "summary": "Краткое содержание"
}
```

## Папка models

Здесь лежат веса базовой модели.

Сейчас используется:

- `rut5_base_sum_gazeta`

Эта модель является основной для проекта и базой для дообучения.

## Папка checkpoints

Здесь сохраняются результаты дообучения.

Пример:

- `checkpoints/rut5-finetuned`

После обучения именно этот путь можно передавать в `main.py` как новую модель.

## Папка tests

Содержит базовые тесты:

- `test_preprocessing.py` — проверка обработки текста
- `test_model.py` — проверка логики длины и обработки summary

## Как связаны файлы

Поток обычной суммаризации:

1. Пользователь запускает `main.py`
2. `main.py` вызывает `src/summar/cli.py`
3. `cli.py` читает текст
4. `cli.py` создаёт `SummarizationModel`
5. `model.py` использует `config.py` и `preprocessing.py`
6. Модель генерирует summary
7. `cli.py` выводит summary и статистику

Поток API:

1. Пользователь запускает `run_api.py`
2. `run_api.py` поднимает `FastAPI`
3. `api.py` принимает текст
4. `api.py` вызывает `model.py`
5. API возвращает JSON с summary

Поток дообучения:

1. Пользователь запускает `train_model.py`
2. `train_model.py` вызывает `src/summar/train.py`
3. `train.py` читает `data/train.json` и `data/validation.json`
4. `train.py` токенизирует данные
5. `transformers` запускает обучение
6. Новый чекпоинт сохраняется в `checkpoints/`
